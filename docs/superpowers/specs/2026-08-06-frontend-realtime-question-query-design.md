# 纯前端实时题目查询设计

## 1. 背景与目标

现有项目已经具备浏览器屏幕共享、区域裁剪、Tesseract.js OCR、本地题目匹配和答案浮层。原方案依赖爬虫预先构建完整题库，但高频、批量抓取容易触发远程站点限流，而且题库更新不够及时。

本次改造将正常使用链路调整为：用户手动选择活动分类，浏览器自动连续识别共享画面中的题目，优先读取 IndexedDB 缓存；缓存未命中时，前端直接调用第三方题库搜索接口。用户自行安装并启用允许跨域请求的浏览器扩展，不引入项目后端。

## 2. 已确认的产品决策

- 交付形态为纯前端静态页面。
- 浏览器直接调用第三方题库接口。
- 使用前由用户手动选择当前活动分类。
- 默认自动连续识别，并保留手动重试按钮。
- 查询采用“清洗后的完整题干主查询 + 一次关键词降级查询”。
- 成功查询结果持久化到 IndexedDB。
- 现有爬虫和本地题库构建脚本保留，但不再是正常使用的必要依赖。

## 3. 范围边界

### 3.1 本次包含

- 连续捕获与题目稳定性确认。
- 远程题库客户端。
- 主查询与一次关键词降级。
- 候选题本地排序。
- 答案文本与当前选项匹配。
- IndexedDB 成功结果缓存。
- 请求去重、取消、冷却和错误反馈。
- 手动重试。

### 3.2 本次不包含

- 项目自建后端或公共代理。
- 多关键词并发查询。
- 自动判断或切换活动分类。
- 自动操作游戏界面。
- 删除现有爬虫、JSON 题库或索引构建能力。
- 将失败结果长期写入缓存。

## 4. 总体架构

```text
用户选择活动分类
→ 授权共享游戏窗口
→ 每秒抽帧约 2 次
→ 裁剪题干与选项区域
→ 帧变化检测
→ OCR 识别
→ 连续两帧稳定性确认
→ 生成题目指纹
→ 查询 IndexedDB
→ 缓存未命中时执行完整题干查询
→ 无结果时执行一次关键词降级查询
→ 本地排序候选题
→ 将答案文本与当前选项匹配
→ 缓存成功结果
→ 显示答案与置信度
```

### 4.1 模块边界

1. **捕获模块**：负责屏幕共享、区域裁剪和帧变化判断，不依赖远程接口。
2. **OCR 模块**：输出题干、选项、OCR 置信度和耗时。
3. **题目稳定器**：比较连续 OCR 结果，过滤动画、翻页中间态和残缺文字。
4. **远程题库客户端**：负责请求编码、超时、取消、响应解析和错误分类。
5. **候选匹配器**：根据题干、答案和 OCR 置信度对候选题排序。
6. **答案解析器**：将答案文本与当前 A/B/C/D 选项比较，推导答案字母。
7. **缓存模块**：持久化成功结果，维护访问时间与命中次数。
8. **识别调度器**：串联所有模块，保证 OCR 与远程请求不会失控并发。

各模块通过明确数据结构通信，不直接读取其他模块内部状态。

## 5. 远程查询设计

### 5.1 请求协议

目标接口：

```text
https://s.175dt.com/?id=<categoryId>&kw=<queryText>&c=10000
```

所有参数使用 `URLSearchParams` 编码。单次请求超时为 1.5 秒；一道题最多请求两次，完整远程查询流程最大等待约 3 秒。同一时刻只允许一个远程请求；发现用户已经切换到下一题时取消旧请求。

远程客户端返回以下结构化状态之一：

- `success`：返回有效候选题。
- `empty`：请求成功但没有候选题。
- `corsBlocked`：请求表现符合跨域拦截特征。
- `timeout`：请求超时。
- `rateLimited`：返回 403 或 429。
- `remoteError`：其他远程错误。
- `malformedResponse`：响应格式不符合约定。

浏览器无法准确区分 CORS、扩展状态与普通网络故障，因此界面只能提示“可能是 CORS 或网络错误”，不能断言扩展未启用。

### 5.2 主查询

OCR 题干执行轻度清洗后作为第一次查询文本：

- 删除换行、选项编号和多余空格。
- 统一全角、半角标点。
- 删除明显的 OCR 符号噪声。
- 保留汉字、数字、专有名称和有意义的标点内容。
- 不进行激进拼写纠错。

### 5.3 一次关键词降级

只有主查询明确返回空结果时才降级。超时、限流、CORS 或响应损坏不会立即触发第二次请求。

关键词按以下优先级选取：

1. 引号或书名号中的专有内容。
2. 朝代、人名、地名、作品名等连续中文词组。
3. 数字与量词组合。
4. 题干中长度为 2～4 的高信息量片段。

“以下、哪个、什么、正确、错误、属于”等通用问句词不得作为降级关键词。每道题只选一个降级关键词，不并发尝试多个词。

## 6. 候选排序与答案解析

候选题综合分数为：

```text
总分 = 题干字符相似度 × 70%
     + 答案与选项相似度 × 20%
     + OCR 置信度 × 10%
```

结果阈值：

- 分数不低于 `0.82`：显示确定答案。
- 分数在 `0.68` 至 `0.82` 之间：显示答案并标记低置信度。
- 分数低于 `0.68`：不显示强答案，等待手动重试。
- 第一、第二候选分差小于 `0.05`：视为存在歧义，展示候选但不强行确定答案。

远程接口返回答案文本而非选项字母。答案解析器必须将答案文本与本次 OCR 识别到的选项重新比较，不能缓存或复用历史选项字母。若找到答案文本但无法可靠对应选项，则只显示答案文本。

## 7. IndexedDB 缓存

成功结果的数据结构：

```ts
interface RemoteQuestionCache {
  id: string
  categoryId: string
  questionFingerprint: string
  recognizedQuestion: string
  matchedQuestion: string
  answerText: string
  source: string
  matchConfidence: number
  createdAt: number
  lastUsedAt: number
  hitCount: number
}
```

缓存主键：

```text
id = categoryId + ":" + questionFingerprint
```

缓存规则：

- 成功匹配结果长期保存。
- 每次命中更新 `lastUsedAt` 和 `hitCount`。
- 空结果、OCR 失败和网络失败不持久化。
- 失败题目仅在内存中冷却 10 秒。
- 403 或 429 使当前分类的远程查询冷却 60 秒。
- 缓存命中后仍使用当前选项重新推导答案字母。
- 设置面板支持按分类清理和全部清理。

## 8. 连续识别状态机

核心状态：

```text
idle
capturing
frameChecking
recognizing
stabilizing
cacheLookup
primaryQuery
fallbackQuery
matching
showingAnswer
waitingRetry
paused
```

调度规则：

- 使用串行异步循环，不叠加多个独立 `setInterval`。
- 每轮处理完成后等待约 500ms，再捕获下一帧。
- 同一时间最多存在一个 OCR 任务和一个远程请求。
- 连续两次标准化 OCR 题干相似度达到 `0.9` 才认定为稳定题目。
- 当前题与上一道已完成题相似度高于 `0.95` 时不重复查询。
- 请求期间发现题目已经切换时，取消旧请求并丢弃其结果。
- 切换分类、屏幕共享停止或用户暂停时，取消当前任务并清空题目稳定器。
- 切换分类不删除其他分类的缓存。

## 9. 自动识别与手动重试

自动模式发现稳定新题后，依次执行缓存查询、必要的远程查询、候选排序和答案展示。

手动重试行为：

- 立即重新截取当前画面并执行 OCR。
- 绕过 10 秒失败冷却。
- 仍优先使用成功缓存。
- 手动任务优先于自动任务，并取消尚未完成的自动请求。
- 手动任务与自动任务不得并发修改当前答案状态。

## 10. 用户界面反馈

主界面应显示当前处理阶段：

- 等待画面。
- 正在识别。
- 正在确认题目。
- 正在查询本地缓存。
- 正在查询远程题库。
- 正在使用关键词重试。
- 已找到答案。
- 结果置信度较低。
- 等待手动重试。

答案区域显示推荐选项字母、答案文本、匹配到的原始题目、综合置信度、结果来源和本次总耗时。

错误反馈要求：

| 场景 | 页面反馈 | 行为 |
|---|---|---|
| 屏幕共享被拒绝 | 无法获取共享画面 | 返回授权步骤 |
| 共享流结束 | 屏幕共享已停止 | 暂停识别 |
| OCR 初始化失败 | OCR 引擎加载失败 | 允许重新初始化 |
| OCR 不稳定 | 正在等待清晰题目 | 自动继续抽帧 |
| 网络层 `TypeError` | 可能是 CORS 或网络错误 | 展示扩展检查说明 |
| 请求超时 | 远程题库响应超时 | 当前题冷却 10 秒 |
| 403 或 429 | 接口暂时拒绝请求 | 当前分类冷却 60 秒 |
| 返回格式异常 | 远程接口格式发生变化 | 保留错误摘要 |
| 没有候选题 | 当前题目未查询到 | 提供手动重试 |
| 答案无法对应选项 | 无法确定选项字母 | 仅显示答案文本 |
| 候选存在歧义 | 找到多道相似题 | 展示前两条候选 |

## 11. 测试与验收

### 11.1 单元测试

- OCR 文本清洗。
- 题目指纹生成。
- 降级关键词选择。
- 候选题相似度计算。
- 答案文本与选项匹配。
- 连续两帧稳定性判断。
- 缓存键和缓存更新规则。
- 接口响应解析和错误分类。

### 11.2 接口模拟测试

- 主查询直接命中。
- 主查询为空、降级查询命中。
- 两次查询均为空。
- 请求超时。
- 403、429 和 500 响应。
- 非 JSON 响应。
- 缺少 `hits` 字段。
- 用户切题后旧请求被取消。

### 11.3 浏览器人工验收

- 启用允许跨域扩展后能够直接查询。
- 未启用扩展时反馈清晰且不会无限重试。
- 连续显示同一道题不会重复请求。
- 快速切题不会显示上一题答案。
- 选项顺序变化后能够重新确定答案字母。
- 切换活动分类后使用正确分类 ID 查询。
- 刷新页面后成功缓存仍然存在。
- 手动重试能够绕过失败冷却。
- 停止屏幕共享后不再识别或请求。

## 12. 实施原则

- 沿用现有 Vue 3、TypeScript、Pinia、Tesseract.js 和 `idb` 技术栈。
- 新能力按远程客户端、稳定器、缓存和调度器拆分，避免将所有逻辑堆入组件或单一 Store。
- 所有方法必须提供说明职责的中文注释。
- 不为迎合单元测试增加运行时无意义分支或重复接口。
- 现有爬虫和构建脚本不做无关重构。
